    6.1. 引言

    现在，我们计划为应用程序添加会话管理功能。请回顾以下要点：

    • HTTP 客户端-服务器对话是由一系列彼此独立的请求-响应序列组成的
    • 会话在同一用户的不同请求-响应序列之间起到记忆作用。如果有 N 个用户，则会有 N 个会话。

    以下屏幕截图展示了当前应用程序运行时所需的效果：

    在交互1中，用户为(姓名,年龄)这对数据提供了值(xx,yy)。如果服务器在交互过程中获取了这些值，那么在交互结束时，它会“忘记”这些值。 然而，我们可以发现，在第2次交互中，服务器却能在响应中重新显示这些值。正是“会话”这一概念，使得Web服务器能够在后续的客户端-服务器交互过程中记住数据。当然，还有其他可能的解决方案来解决这个问题。

    在第1次交互过程中，服务器会将客户端发送的(姓名,年龄)数据对存储在会话中，以便在第2次交互时显示出来。

<property name="context-root" value="personne2"/>

    更新内容：

    • 第19行，表单现在有一个名为 [action] 的属性，其值为当用户点击类型为 submit 的 [Envoyer] 按钮时，浏览器应将表单值提交到的 URL。 变量 [urlAction] 的值将变为 action="main"。在用户执行以下操作后，将显示视图 [formulaire]：

    • 第8行：获取模型中[urlAction]元素的值。该值在当前请求的属性中查找，将在第19行使用。

        // 获取发送请求的方法
        String méthode=request.getMethod().toLowerCase();
        // 获取待执行的操作
        String action=request.getParameter("action");
        // 操作？
        if(action==null){
            action="init";
        }
        // 执行操作
        if(méthode.equals("get") && action.equals("init")){
            // 启动应用程序
            doInit(request,response);
            return;
        }
        if(méthode.equals("post") && action.equals("validationFormulaire")){
            // 验证输入表单
            doValidationFormulaire(request,response);
            return;
        }
        if(méthode.equals("get") && action.equals("retourFormulaire")){
            // 返回输入表单
            doRetourFormulaire(request,response);
            return;
        }
        // 其他情况
        doInit(request,response);
    }
    • 第 6-14 行：检查初始化错误列表是否为空。若非如此，则显示视图 [erreurs(erreursInitialisation)] 以报告相关错误。

    void doRetourFormulaire(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException{
        // 获取用户会话

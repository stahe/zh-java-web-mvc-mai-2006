    [ref1] 读取内容：第 1 章，第 2 章：2.2、2.2.1、2.2.2、2.2.3、2.2.4

    先前的客户端/服务器架构转换如下：

    JSP 页面是 HTML 页面的参数化形式。页面中的某些元素仅在运行时才获得其值。这些值由程序计算得出。 因此，这是一个动态页面：对该页面的连续请求可能会产生不同的响应。这里所说的响应，是指客户端浏览器显示的 HTML 页面。最终，浏览器收到的始终是一个 HTML 文档。 该 HTML 文档由 Web 服务器基于 JSP 页面生成。后者作为模板，其动态元素在生成 HTML 文档时被替换为当时的实际值。

    // 获取参数

    通过引入Java代码，原本静态的文档现已变为动态文档。对于此类文档，我们将始终按照以下步骤操作：

    • 在文档开头插入Java代码，以获取文档显示所需的参数。这些参数通常位于request对象中。该对象代表客户端的请求。该请求可能经过多个Servlet和JSP页面，这些组件可能对其进行了扩展。在此处，它将直接从浏览器传入。
    • 后续是 HTML 代码。它通常仅通过 <%= 变量 %> 标签显示在 Java 代码中预先计算的变量。需注意此处等号（=）紧贴百分号（%），这是常见的错误原因。

    前面的动态文档起什么作用？

    • 第 6-9 行：它从查询中提取两个名为 [txtNom] 和 [txtAge] 的参数，并将它们的值赋给变量 [nom]（第 6 行）和 [age] （第8行）。如果找不到这些参数，则为相关变量赋予默认值。
    • 并在随后的代码 HTML 中显示这两个变量的值（第 25 行和第 29 行）。

    3.6.2. Eclipse 项目的类路径

    Java 应用程序的 Classpath 是指编译器在编译该应用程序时，或运行时所遍历的所有文件夹和 archives.jar。 这两个Classpath不一定完全相同，因为某些类仅在运行时有用，而在编译时则无用。 无论是 Java 编译器还是运行时环境，都提供了一个参数，用于指定要编译或运行的应用程序。Eclipse 会以对用户而言或多或少透明的方式，负责构建该参数并将其传递给运行时环境。

    仅从Servlet的代码来看，便可发现它比对应的JSP页面复杂得多。这是一个普遍现象：Servlet并不适合生成HTML代码。 JSP 页面才是为此设计的。我们稍后会再讨论这一点。下面我们来解释一下上述 Servlet 的几个要点：

    • 当 Servlet 被首次调用时，会调用其 init 方法（第 20 行）。这是该方法被调用的唯一情况。
    • 如果 Servlet 是由方法 HTTP 或 GET 调用的，则会调用方法 doGet（第 32 行）来处理客户端的请求。
    • 如果 Servlet 是由方法 HTTP POST 调用的，则会调用方法 doPost（第 82 行）来处理客户端的请求。

    此处的 init 方法用于从 [web.xml] 中获取名为“defaultNom”和“defaultAge”的初始化参数值。 在 Servlet 初始加载时执行的 init 方法是获取 [web.xml] 文件内容的合适位置。

    • 第 22 行：获取 Web 项目的 [config] 配置。该对象反映了应用程序中 [WEB-INF/web.xml] 文件的内容。
    • 第 23 行：从该配置中获取名为“defaultNom”的参数的 String 类型值。该参数的值将是一个人的姓名。 若该参数不存在，则将获取值 null。
    • 第24-25行：如果名为“defaultNom”的参数不存在，则为变量[defaultNom]赋予默认值。
    • 第 26-29 行：对名为“defaultAge”的参数也进行同样的处理。

    方法 doPost 调用了方法 doGet。这意味着客户端既可以通过 POST，也可以通过 GET 发送其参数。

    方法 doGet：

    • 第 32 行：该方法接收两个参数 request 和 response。request 是一个对象，代表客户端的完整请求。其类型为 HttpServletRequest，这是一个接口。response 的类型为 HttpServletResponse，同样是一个接口。response 对象用于向客户端发送响应。
    • request.getParameter("param") 用于从客户端请求中获取名为 param 的参数值。 第 36 行，获取参数 "txtNom" 的值；第 40 行，获取参数 "txtAge" 的值。 如果请求中不存在这些参数，则将 null 作为参数值。
    • 第37-39行：如果请求中不包含参数“txtNom”，则将初始化方法init中设定的默认值“defaultNom”赋给变量“nom”。 第41-43行对年龄的处理方式相同。
    • 第 45 行：response.setContentType(String) 用于设置 HTTP Content-type 标头的值。该标头向客户端指示其将接收的文档类型。text/html 类型表示 HTML 文档。
    • 第 46 行：response.getWriter() 用于获取向客户端的写入流
    • 第47-78行：将要发送给客户端的文档写入第46行获取的写入流中

    3.7. Servlet 与 JSP 页面的协作

    参考资料 [ref1]：第 2 章：2.3.7

    让我们回到之前探讨的两种架构：

    这两种架构均不尽如人意。它们都存在将两种技术混为一谈的弊端：一种是负责Web应用程序逻辑的Java编程技术，另一种是负责在浏览器中呈现信息的HTML编码技术。

    • 基于 JSP 页面的 [1] 方案存在一个缺点，即在同一页面内混合了 HTML 代码和 Java 代码。 在处理的这个基础示例中，我们并未遇到此问题。但如果 [formulaire.jsp] 需要验证客户端请求参数 [txtNom, txtAge] 的有效性，我们就不得不将 Java 代码放入页面中。这很快就会变得难以管理。
    • 基于Servlet的解决方案同样存在这个问题。尽管类中只有Java代码，但它必须生成一个文档。 同样地，除非 HTML 文档结构简单，否则其生成过程将变得复杂，且几乎无法维护。

    我们将通过采用以下架构来避免 Java 与 HTML 技术的混合：

    • 用户向 Servlet 发送请求。Servlet 处理该请求并构建页面 JSP [formulaire.jsp] 的动态参数值，这些参数将用于向客户端生成响应 HTML。 这些值共同构成了所谓的页面模板 JSP。
    • 完成工作后，Servlet 将请求页面 JSP [formulaire.jsp] 向客户端生成响应 HTML。 同时，它还将向客户端提供页面 JSP 生成该响应所需的元素，这些元素构成了该页面的模型。

    现在，我们将探讨这一新架构。

import javax.servlet.ServletConfig;
import javax.servlet.ServletException;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;

@SuppressWarnings("serial")
public class ServletFormulaire2 extends HttpServlet {

    // 实例参数
    private String defaultNom = null;

    private String defaultAge = null;

    // 初始化
    public void init() {
        // 获取 Servlet 的初始化参数
        ServletConfig config = getServletConfig();
        defaultNom = config.getInitParameter("defaultNom");
        if (defaultNom == null)
            defaultNom = "NNNNNNNNNNNNNNN";
        defaultAge = config.getInitParameter("defaultAge");
        if (defaultAge == null)

    // GET
    public void doGet(HttpServletRequest request, HttpServletResponse response)
            throws IOException, ServletException {

        // 获取表单参数
        String nom = request.getParameter("txtNom");
        if (nom == null) {
            nom = defaultNom;
        }
        String age = request.getParameter("txtAge");
        if (age == null) {
            age = defaultAge;
        }
        // 显示表单
        request.setAttribute("nom", nom);
        request.setAttribute("age", age);
        getServletContext().getRequestDispatcher("/formulaire2.jsp").forward(request, response);

    // POST
    public void doPost(HttpServletRequest request, HttpServletResponse response)
            throws IOException, ServletException {
        // 将控制权移交给 GET
        doGet(request, response);

    3.7.3. 应用程序配置

    配置文件 [web.xml] 修改如下：

    
<?xml version="1.0" encoding="UTF-8"?>
<web-app id="WebApp_ID" version="2.4"
    xmlns="http://java.sun.com/xml/ns/j2ee"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:schemaLocation="http://java.sun.com/xml/ns/j2ee http://java.sun.com/xml/ns/j2ee/web-app_2_4.xsd">
    <display-name>personne</display-name>
    <!--  ServletFormulaire -->
    <servlet>
        <servlet-name>formulairepersonne</servlet-name>
        <servlet-class>
            istia.st.servlets.personne.ServletFormulaire
        </servlet-class>
        <init-param>
            <param-name>defaultNom</param-name>
            <param-value>inconnu</param-value>
        </init-param>
        <init-param>
            <param-name>defaultAge</param-name>
            <param-value>XXXX</param-value>
        </init-param>
    </servlet>
    <!--  ServletFormulaire 2-->
    <servlet>
        <servlet-name>formulairepersonne2</servlet-name>
        <servlet-class>
            istia.st.servlets.personne.ServletFormulaire2
        </servlet-class>
        <init-param>
            <param-name>defaultNom</param-name>
            <param-value>inconnu</param-value>
        </init-param>
        <init-param>
            <param-name>defaultAge</param-name>
            <param-value>XXX</param-value>
        </init-param>
    </servlet>
    <!--  映射 ServletFormulaire -->
    <servlet-mapping>
        <servlet-name>formulairepersonne</servlet-name>
        <url-pattern>/formulaire</url-pattern>
    </servlet-mapping>
    <!--  映射 ServletFormulaire 2-->
    <servlet-mapping>
        <servlet-name>formulairepersonne2</servlet-name>
        <url-pattern>/formulaire2</url-pattern>
    </servlet-mapping>
    <!--  欢迎文件 -->
    <welcome-file-list>
        <welcome-file>index.html</welcome-file>
    </welcome-file-list>
</web-app>

    我们保留了原有内容并添加了：

    • 第 22-36 行：添加一个 <servlet> 部分，用于定义新的 ServletFormulaire2 Servlet
    • 第 42-46 行：添加一个 <servlet-mapping> 部分，将其与 URL /formulaire2 关联
